## 6. Target Selection

Request generations and aborts prevent stale search results. Durable saved symptoms and catalog symptoms retain distinct identities; optional condition scope is supported. ## 7. Intervention Flow

## 8. Experiment Design

Editable name, question, analysis timezone, historical baseline dates and intervention dates are supported. History defaults come from discovery; presets offer 7/14/28 intervention days, with custom dates editable. No-baseline mode appears only where supported. Saved prospective designs must be changed before Start; no unsupported prospective request is dispatched. Custom questions and saved secondary outcomes/success criteria survive restore/save.

## 9. Baseline Readiness UX

The existing readiness API supplies all classifications and data facts. Good, limited, insufficient and operationally unavailable states have distinct text. Limited/insufficient complete reads can continue; technical failures require retry before Start. Workout wording distinguishes latest/best Estimated 1RM; nutrition distinguishes complete coverage and unknown intake; recorded-event zero is not described as proven absence. No thresholds, analytics or replacement readiness are calculated in React.

## 10. Readiness Staleness Handling

The preview identity includes the complete primary-outcome configuration, target, aggregation, timezone, baseline mode and baseline bounds. A mismatch hides the prior result immediately and asks for a new check. Request generations suppress both stale success and stale failure responses. Draft loads are also generation-guarded so older responses cannot overwrite newer loads. Changing only the name/question does not invalidate measurement readiness.

## 11. Review Experience

Review shows the question, measurement/target, saved change, comparison window, experiment period/timezone and current readiness. Existing success criteria and secondary-outcome preservation are disclosed. Copy states that observations show associations, not causation, and the start transaction—not the preview—is authoritative.

## 12. Draft Save and Duplicate-Creation Safety

There is no autosave or automatic mutation retry. DraftSession takes its busy lock synchronously, before awaiting, preventing duplicate null-ID create clicks. A valid create response immediately becomes authoritative ID/revision state. Subsequent saves send that ID and current revision. Responses must have the expected ID, next revision and draft status. Network/timeout, ambiguous server or malformed success responses lock mutation controls; an uncertain new create is not retried. The user must inspect Your experiments. This is client duplicate protection, not a claim of backend create idempotency or cross-tab deduplication.

## 13. Revision Conflict Behavior

Conflicts surface rather than overwrite. Mutations are blocked until an explicit reload of the latest draft; confirmation warns that unsaved edits will be discarded. Restore adopts the server revision. The client never silently merges or retries a stale revision.

## 14. Start Flow

Start uses only the authenticated HTTP endpoint, with the saved ID/current revision. Dirty, incomplete, prospective or technically unchecked configurations cannot start. An immediate busy lock prevents concurrent submissions; a terminal started flag prevents another submission while navigation completes. Success routes to `/experiments/{id}?started=1`. No direct experiment RPC was introduced in v2 browser code.

## 15. Premium Upgrade Flow

Server Premium errors render the existing UpgradeCard and pricing link. No entitlement is inferred from discovery or calculated locally. Free users can explore and read saved drafts. Rejected Premium mutations retain configuration for explicit retry after upgrading; checkout itself was not exercised.

## 16. Legacy / V2 Detail Behavior

The model-version branch precedes legacy action construction. V1 detail retains its original lifecycle controls. V2 detail is read-only status/configuration, with draft review navigation and an active-phase confirmation. V2 does not expose legacy activate/pause/transition or legacy results controls.
