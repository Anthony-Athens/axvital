# Sprint 3 — food resolution and component review

1. **Existing architecture.** Sprint 1 routes health-event writes through `lib/health-events/ingestion.ts`, retaining dates, times, tags and input method. Sprint 2 produces reviewed voice candidates and saves a mixed batch only after confirmation. The activity timeline reads `health_events`. Manual Food Quick Log opens the separate nutrition workflow: `nutrition_entries` and `nutrition_entry_items`, with serving/nutrient snapshots written by `log_food_atomic`. Existing global `foods`, `food_aliases`, `food_categories` and `food_category_map` supply reference data. Existing classification assertions and experiment evidence are separate systems. This sprint does not bridge or duplicate their records.

2. **Schema/migrations.** `202609240003_food_intelligence.sql` adds `food_components`, `health_event_foods`, `health_event_food_components`, an invoker category view and an atomic invoker ingestion RPC. Event-to-food rows have a unique health-event relationship; components are children of that relationship. Ownership is enforced with both RLS and composite foreign keys. The migration extends the fail-closed account schema inventory/export and the shared API budget. `202609240004_starter_composite_foods.sql` seeds reference foods, aliases, categories and component edges idempotently.

3. **Matching hierarchy.** Exact canonical name → exact alias → normalized canonical name/alias → conservative fuzzy match → optional AI → provisional label. Existing Sprint 1 normalization is reused. Matching treats hyphens/commas as word boundaries and collapses whitespace. Safe quantity prefixes and ingredient clauses can be separated from the primary name. Fuzzy matching permits only one edit in one long token of an otherwise identical multiword name. Ambiguous matches stop without an arbitrary winner, including ambiguity after quantity removal.

4. **Aliases/duplicates.** `common_aliases` and `food_aliases` are combined. Coke Zero, Coca Cola Zero and Coca-Cola Zero Sugar resolve to one canonical entry. Preparation/brand tokens are not dropped: chicken breast and grilled chicken breast remain distinct. Resolution never inserts global foods. Seeds check normalized name equivalence, unique slugs and existing relationships before adding records; existing ambiguous data is not merged.

5. **Composite model.** Global edges connect parent/component canonical foods, with constrained provenance, optional confidence and timestamps. Resolution traverses one level only, capped at 16 components. A pizza remains one visible health event with its original title/amount. No component or category creates another timeline event.

6. **Event-specific reality.** Review copies typical components into an event draft. Explicit clauses override library selections; “without cheese” retains an excluded component row. Saving stores the reviewed selection independently of global edges. Mixed food/non-food events and all relationship rows commit in one transaction through `ingest_health_events_with_food`. Existing batches without food metadata retain their original single-insert path. No automatic retry is introduced after uncertain transport failures.

7. **Provenance.** Sources are `library`, `explicit`, `ai_inferred`, and `user_confirmed`. Individual confirmation is a separate boolean, preserving a component's original source when its checkbox changes. Renaming/adding a component creates user-confirmed, unmatched data and clears stale canonical categories/confidence. AI suggestions remain `ai_inferred` even if the model supplies a quote; deterministic ingredient clauses are the authority for `explicit`. Raw AI output and evidence quotes are not persisted.

8. **Categories.** Categories are derived from selected canonical component mappings, preserving many-to-many relationships. Exclusions contribute no positive exposure. Simple foods without components use their primary mappings; a simple food with additions retains the base as a component (bread with cheese → grains and dairy). Unconfirmed AI components and unconfirmed simple AI/fuzzy parent matches contribute no category exposure. The invoker view retains source/confirmation/confidence, rather than treating classifications as verified intake. This view is not connected to experiments, correlations or nutrition totals. Category mappings remain current reference data, not immutable historical category snapshots.

9. **Review UI.** Food/fluid cards have optional expandable details showing the catalog match, component source and confirmation, selected possible categories, exclusion checkboxes, corrections and additions. AI components start unchecked. Suggested AI/fuzzy primary matches can be confirmed or discarded. Editing a primary name/type clears stale food metadata. “Match food again” uses the edited label, not the old transcript. Pending matching blocks confirmation, is bounded and aborts on unmount; failure leaves the original label saveable. Existing manual Quick Log stays unchanged. Reference-only seed foods are excluded from the serving-based manual nutrition picker.

10. **AI behavior.** Server-only Responses integration uses strict JSON Schema, `store:false`, the existing server key/model configuration, a 12-second deadline and at most three concurrent unresolved-food enrichments per voice request. Catalog resolution always runs first. AI can only reference IDs in the loaded catalog. Closed-key validation rejects malformed output, invalid IDs/confidence, invented structured quantities/nutrients and unsupported explicit evidence. Library components take precedence after an AI parent suggestion. Optional AI failures/refusals/missing credentials preserve provisional drafts. AI does not write taxonomy, estimate nutrition, diagnose, recommend diets or claim causation. The resolver endpoint requires authentication, same origin, bounded JSON and a shared six-per-minute user budget. No diet details are sent to behavioral analytics.

11. **Starter library.** Nine composite entries: pepperoni pizza, cheese pizza, turkey sandwich, cheeseburger, peanut butter sandwich, Greek yogurt with berries, salad with chicken, tacos and cereal with milk. Fifteen supporting/reference entries include crust, cheese, tomato sauce, pepperoni, bread, turkey, mayonnaise, lettuce, beef patty, bun, berries, chicken, tortilla, cereal and Coca-Cola Zero Sugar. Existing Greek yogurt, milk, peanut butter, mixed greens and oatmeal records are reused or left intact. Turkey sandwich defaults only to bread and turkey; optional toppings require explicit input/review. Tacos only supplies a tortilla component rather than guessing a filling. No servings or nutrient numbers are invented.

12. **Access model.** Authenticated users read active global references and cannot mutate trusted taxonomy. Both private tables permit only owner CRUD, require a visible owner parent and restrict new canonical references to active foods. Composite ownership foreign keys block cross-owner links. Anonymous access is revoked. The ingestion function and category view run with caller privileges; no service-role client is used. Existing health-event policies are unchanged. Account export includes private relationships; account deletion cascades them while preserving global knowledge and other owners' data. API logs contain fixed operation categories, not food/transcript payloads.

13. **Files changed.** New runtime files: `components/checkin/FoodReview.tsx`; `app/api/nutrition/resolve/route.ts`; `lib/nutrition/food-resolution.ts`, `food-catalog.ts`, `food-service.ts`, `food-ai.ts`; the two migrations above. Integration edits: `components/checkin/VoiceLogDialog.tsx`, `app/api/voice-log/parse/route.ts`, `lib/voice/api.ts`, `lib/voice/schema.ts`, `lib/api/validation.ts`, `lib/health-events/ingestion.ts`, `lib/nutrition/nutrition.ts`. Tests: four new `lib/nutrition/food-*.test.ts` files, expanded `lib/voice/ui.test.ts`, and a UTC default in `lib/security/test-database.ts`. This report is the documentation addition.

14. **Tests added.** Deterministic matching/alias/ambiguity/preparation cases; pizza, sandwich, burger and yogurt decomposition; exclusion/provenance/category behavior; bounded nonrecursive traversal; AI gating and fallback; mixed voice enrichment and atomic ingestion contract; strict mocked-provider validation/privacy; authenticated resolver bounds/budgets; real PostgreSQL migrations, seed idempotence, rollback, owner isolation, global write denial, account export/deletion; UI exclusions, editing, uncertain-save acknowledgement and retry without component events. Existing regression assertions were retained. The synthetic test database now explicitly uses UTC: existing experiment fixtures declared UTC analysis dates but previously inherited the host timezone, causing date-dependent failures after UTC midnight.

15. **Verification.** `npm test`: **666 passed, 0 failed**. `npm run typecheck`: **passed**. `npm run lint`: **passed**. `npm run build`: **passed** (Next.js 16.3.3 production build). Esbuild-based tests required the approved Windows sandbox file-access exception. The earlier UTC/local-date fixture failures were resolved by setting the synthetic database's timezone, without weakening assertions. PostgreSQL integration tests use PGlite and the repository migration chain. The original baseline table DDL is absent from the repository, so tests extend the documented synthetic `health_events` baseline with the fields needed by the new RPC. This is not proof of a deployed Supabase schema. Browser behavior is tested through JSDOM and mocked recording/network providers.

16. **Limitations and rollout.** Migrations are local and have not been applied to a live database. Apply both migrations in order before deploying the application. No live AI, microphone, physical-device or deployed-RLS behavior was tested. The intentionally small catalog and conservative ingredient grammar leave uncertain foods/components unmatched. Catalog reads fail safely at the 1,000-row boundary; AI is disabled above 250 foods rather than sending an unbounded catalog. Component corrections are saved as entered and do not automatically classify new labels. Component review is currently in Voice Log; post-save component editing and a voice-to-nutrition snapshot bridge are deferred. Unknown foods remain saveable when optional enrichment fails, but enriched persistence requires the new migration. Migration inventory patches fail closed if prior account functions differ from the expected repository definitions.

17. **Recommended Sprint 4.** Add catalog curation/versioning and a small reviewed alias workflow; improve event component editing and explicit canonical selection; validate live Supabase policies and mobile voice/review behavior in staging. Design an opt-in voice-to-manual-nutrition bridge only when serving quantities and existing nutrient snapshots can be reviewed explicitly. Preserve uncertainty and provenance before considering future category-based analysis.
